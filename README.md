# AICoding Exam Playbook

一套面向 AICoding 笔试的中文解题手册，基于两次真实笔试经历和本地开发 Skills 的机制拆解，重点处理长题面、Agent 能力差异、测试纠错、范围越界与最终验收。

> 当前状态：初版。内容来自有限实战样本，适合作为临场工作框架，不代表所有 AICoding 平台都遵循相同规则。

## 核心方法

方法论主循环可以记成七个字：

```text
读 → 锁 → 切 → 测 → 做 → 修 → 收
```

- **读**：让 Agent 接触 README、当前代码、测试入口和真实报错，并先识别文件角色。
- **锁**：以 README 为需求源，压缩出 P0、验收和明确排除项。
- **切**：由人判断任务数量，每个任务对应一条可验证的纵向业务切片。
- **测、做、修**：用真实测试推动实现；同一错误反复出现时基于新证据诊断并及时止损。
- **收**：分别检查需求覆盖和工程实现，最后运行完整测试与平台验收。

## 两条实战路线

### 稳健路线

适合弱模型、人工运行测试、隐藏测试不透明或错误容易反复的场景：

```text
一个任务 → 一个测试 → 最小实现 → 同一测试复验 → 下一行为
```

### 快速路线

适合能够自主读取项目、修改代码并运行测试的高能力 Agent：

```text
人确定任务数量与范围
→ Agent 批量实现批准任务并测试
→ 新会话独立审查
→ 单问题定点修复
→ 最终验收
```

快速路线减少逐测试对话，但不省略范围、测试、审查和验证。

## 使用方式

1. 先根据 Agent 能力、时间、Token 和测试权限选择路线。
2. 每次只复制当前阶段的一段 Prompt，并填写其中的任务范围、排除项和真实结果。
3. 若题目允许，可创建临时 `AICODING_STATE.md` 保存跨会话状态；如果额外文件会影响判分，则将其放在提交范围外。
4. 只把实际运行通过的测试标记为通过，不用“已经修改”代替“已经验证”。
5. 根据新的真实笔试反馈继续修订，而不是把单次经验固化为通用规则。

## 适用边界

- 本仓库是方法论与 Prompt 集合，不包含可运行的软件工程或自动验收工具。
- 不推测隐藏测试源码，只根据 README、公开示例和平台业务反馈构造本地验证。
- Prompt 无法弥补模型能力、上下文读取或测试权限的根本限制；必要时应缩小范围并优先保证 P0 主链。
- 当前没有声明开源许可证；在许可证补充前，请勿默认获得复制、修改或再分发授权。
